工作原理
******************

Streaming 应用采用精心设计的数据传输路径，以最小的数据丢失实现高速、连续的数据流。

数据路径
==========

.. TODO add picture of the data path

Streaming 应用使用以下数据传输路径：

**Inputs → FPGA → DDR → Processor → Ethernet → Network → PC**

此路径中的每个组件在数据流过程中都承担特定作用：

* **Inputs：** 来自 BNC 连接器的模拟信号
* **FPGA：** 高速 ADC 数据采集和 DMA 控制器
* **DDR：** 用于临时数据存储的乒乓缓冲区
* **Processor：** 运行数据流服务器应用的 ARM CPU
* **Ethernet：** 网络接口（千兆以太网控制器）
* **Network：** 与客户端的 TCP/IP 连接
* **PC：** 接收数据流的客户端应用

.. note::

    对于传输到 SD 卡的本地数据流，数据路径类似，但会将以太网和网络组件替换为 SD 卡接口：

    **Inputs → FPGA → DDR → Processor → SD card**

ADC 数据流架构
***************************

FPGA 到 DDR 的传输
=====================

FPGA 将数据直接从快速模拟输入传输到 DDR 内存。直接内存访问可确保最低延迟和最大吞吐量。

主要特点：

* **直接数据流：** FPGA 中没有中间缓冲。
* **硬件加速：** FPGA 处理所有 ADC 数据采集。
* **连续运行：** 数据从 ADC 连续流向 DDR。

|

乒乓缓冲机制
============================

DDR 内存中使用两个乒乓缓冲区存储数据。此双缓冲技术可确保数据流连续且不中断。

**缓冲区操作：**

1. FPGA 填充 **Buffer A**，同时处理器从 **Buffer B** 读取
2. **Buffer A** 填满后，FPGA 置位“buffer full”标志
3. FPGA 检查处理器是否已完成读取 **Buffer B**
4. 如果读取完成：
   
   * FPGA 切换为填充 **Buffer B**
   * 处理器切换为读取 **Buffer A**

5. 如果读取未完成：
   
   * FPGA 报告缓冲区覆盖错误
   * 丢弃 **Buffer B** 中的当前数据（数据丢失）
   * FPGA 开始覆盖 **Buffer B**

该机制支持连续数据流，但要求处理器跟上数据速率，以避免数据丢失。

|

处理器到网络的传输
===============================

处理器从 DDR 内存读取数据并将其转换为以太网数据包，然后通过网络发送到远程计算机。

**处理步骤：**

1. **从 DDR 读取：** 处理器从已填充的缓冲区获取数据
2. **数据转换：** （可选）如果请求，则从 RAW 转换为 VOLTS。
3. **数据包创建：** 将数据打包为指定块大小的网络数据包
4. **网络传输：** 通过以太网将数据包发送到远程客户端

数据以指定大小的块（数据包）传输，可在 :ref:`内存配置设置 <stream_memory_config>` 中配置。

|

DAC 数据流架构
***************************

DAC 数据流的逻辑与 ADC 数据流对称，但流水线方向相反：

**PC → Network → Ethernet → Processor → DDR → FPGA → Outputs**

.. note::

    对于 one-pack 模式，数据会预先加载到 DDR 内存，再直接传输到 FPGA，无需持续网络传输。

    也支持从 SD 卡传输，但受 SD 卡速度限制，速率较低。

|

网络到处理器的传输
===============================

1. **数据包接收：** 处理器从网络接收数据包。
2. **数据验证：** 验证数据包完整性和顺序。
3. **缓冲区管理：** 将数据存储到 DDR 内存的乒乓缓冲区。

|

处理器到 FPGA 的传输
============================

1. **DDR 到 FPGA：** FPGA 从 DDR 内存读取数据。
2. **DAC 生成：** FPGA 按指定速率向 DAC 发送数据。
3. **缓冲区切换：** 乒乓缓冲区确保连续生成。

|

性能注意事项
===========================

由于流水线方向相反，Red Pitaya 上接收数据的客户端不像 ADC 数据流那样拥有计算机上的大型高速缓冲区，因此预期性能低于 ADC 数据流。

主要差异：

* **缓冲有限：** Red Pitaya 的内存空间少于计算机。
* **上传限制：** 网络上传速度可能低于下载速度。
* **处理开销：** 需要额外的数据验证和缓冲。

因此，:ref:`DAC 数据流限制 <stream_dac_limitations>` 比 ADC 数据流限制更严格。

内存管理
******************

深度存储模式（DMM）集成
====================================

Streaming 应用与 :ref:`深度存储模式 <deepMemoryMode>` 共享保留内存区域。这种共享内存架构具有以下优点：

* **灵活分配：** 可以在 ADC、DAC 和 GPIO 数据流之间动态分配内存。
* **大缓冲区：** 保留内存默认最多 32 MB，也可以更多。
* **高效利用：** 一种模式未使用的内存可以分配给另一种模式。

有关管理保留内存的详情，请参见 :ref:`内存配置 <stream_memory_config>`。

|

块大小和内存分配
==================================

块大小决定通过网络发送的每个数据包大小，而内存分配则在 ADC、DAC 和 GPIO 数据流模式之间划分保留的 DDR 内存。

`CMemoryManager` 类负责内存分配，并在通过 Web 界面或配置文件更改设置时重新分配 DDR 内存缓冲区。客户端应用连接时，这些设置会通过网络传递给客户端。

有关针对具体使用场景选择块大小和分配内存的详细指南，请参见 :ref:`内存配置 <stream_memory_config>`。

|

数据格式与转换
*****************************

数据分辨率和字节分配
=====================================

Streaming 应用支持两种分辨率模式：

* **8 位分辨率：** 每个采样点 1 Byte。
* **16 位分辨率：** 每个采样点 2 Bytes。

.. note::

    即使对于原生 ADC 分辨率为 14 位的板卡（例如 STEMlab 125-14），16 位分辨率模式仍使用每采样点 2 Bytes。额外的 2 位用于填充，以便与标准数据类型对齐。

|

ADC 数据格式
=================

**RAW 格式：**

* 原生 ADC 计数值（STEMlab 125-14 为 14 位）。
* 自动应用校准（OS 2.07-43 及更高版本）。
* 无转换开销。
* 最大性能。
* 需要在计算机上后处理（转换为 Volts）。

**VOLTS 格式：**

* 转换为电压值。
* 自动应用校准。
* 由于转换开销，性能略有降低。
* 可直接使用的数据。

|

将 RAW 值转换为 Volts
================================

RAW 数据包含原生 ADC 计数值。要在计算机上将其转换为 Volts，请将原始整数值除以板卡 ADC 分辨率对应的半量程计数：

.. math::

    V = \frac{RAW}{2^{N-1}} \times V_{range}

其中 :math:`N` 是 ADC 位深度，:math:`V_{range}` 是所选增益设置的峰值输入电压。

对于默认输入范围下的标准板卡：

+------------------------------------------+-------------+---------------+--------------------------------------+
| **Board**                                | **ADC bits**| **Divisor**   | **Default input range**              |
+==========================================+=============+===============+======================================+
| STEMlab 125-14, STEMlab 125-14 Gen 2     | 14-bit      | 8192          | ±1 V (LV) / ±20 V (HV)               |
+------------------------------------------+-------------+---------------+--------------------------------------+
| SDRlab 122-16                            | 16-bit      | 32768         | ±0.25 V                              |
+------------------------------------------+-------------+---------------+--------------------------------------+
| SIGNALlab 250-12                         | 12-bit      | 2048          | ±1 V / ±20 V (selectable)            |
+------------------------------------------+-------------+---------------+--------------------------------------+
| STEMlab 65-16 TI                         | 16-bit      | 32768         | ±1 V (LV) / ±20 V (HV)               |
+------------------------------------------+-------------+---------------+--------------------------------------+

**示例 — STEMlab 125-14，LV（±1 V）：**

.. code-block:: python

    import numpy as np
    import matplotlib.pyplot as plt

    # raw_data is a list/array of 14-bit signed integer ADC counts
    volts = np.array(raw_data, dtype=float) / 8192.0      # result in Volts

    # Plot
    plt.plot(volts)
    plt.ylabel("Voltage (V)")
    plt.xlabel("Sample")
    plt.show()

.. note::

    **数据流中的校准：**

    * **OS 3.00-57 及更高版本** - Streaming 使用校准版本 6（基于 FPGA 的校准）以改善性能。
    * **OS 2.07-43 及更高版本** - RAW 和 VOLTS 数据使用校准版本 5（基于 API 的校准）进行**校准**。
    * **低于 2.07-43 的 OS 版本** - RAW 数据**未经校准**，不会应用 ADC 偏置或增益校准修正。


    对于旧 OS 版本，请使用 **VOLTS** 格式以确保测量经过校准。

文件格式
=============

**BIN（二进制）：**

* 速度最快且最紧凑
* 开销最小
* 分析时需要转换（使用 :ref:`convert_tool <streaming_convert_tool>`）

**WAV（波形音频）：**

* 标准音频格式
* 兼容音频软件
* 最大文件大小为 4 GB
* 为符合格式要求会产生少量开销

**TDMS（技术数据管理数据流）：**

* National Instruments 格式
* 自描述（包含元数据）
* 兼容 |DIAdem| 和 LabVIEW
* 元数据会产生少量开销
