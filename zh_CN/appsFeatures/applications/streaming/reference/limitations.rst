############################
数据流式传输限制
############################

配置数据采集和生成过程时，需要考虑流式传输应用的一些限制。这些限制与最大数据速率和最小流式数据大小有关。

.. contents:: 目录
    :local:
    :backlinks: top

|

1. 数据速率限制
*************************

最大数据速率（每块板卡）由 Red Pitaya 板卡的硬件能力和网络传输速率决定。适用以下限制：

最大数据速率
===================

.. tabs::

    .. group-tab:: OS 2.07-43 or newer

        * **SD 卡流式传输：** 10 MB/s（建议使用 Class 10 SD 卡以获得最佳流式传输性能）
        * **网络流式传输：** 通过 1 Gbit 网络流式传输时为 62.5 MB/s（建议 :ref:`将板卡连接到路由器 <LAN>` 以获得最佳性能）

    .. group-tab:: OS 1.04-28 to 2.05-37

        * **SD 卡流式传输：** 10 MB/s（建议使用 Class 10 SD 卡以获得最佳流式传输性能）
        * **网络流式传输：** 通过 1 Gbit 网络流式传输时为 20 MB/s（建议 :ref:`将板卡连接到路由器 <LAN>` 以获得最佳性能）

最大数据速率的主要限制因素是处理器：它从 DDR 内存缓冲区读取数据，并将数据转换为 Ethernet 数据包进行网络传输。数据路径为：

**Inputs → FPGA → DDR → Processor → Ethernet → Network → PC**.

如果数据速率超过最大可持续速率，处理器将无法跟上输入数据流（在 FPGA 覆盖缓冲区之前读取它），从而导致数据包丢失和数据缺失。:ref:`块大小 <stream_memory_config>` 设置决定每个数据包传输的数据量，但总体限制取决于处理器处理连续数据流的能力。

.. note::

    同时使用多种流式传输模式（例如 ADC 和 DAC 流式传输）会增加处理器负载，从而影响最大数据速率。

|

影响数据速率的因素
=============================

可达到的最大数据速率取决于多个因素：

1.  **处理器开销：** 处理器执行的任何额外处理（例如数据转换、Web 界面更新等）都会降低最大数据速率
2.  **网络配置：** 直接连接与路由器连接、网络拥塞、线缆质量
3.  **SD 卡速度：** 本地流式传输建议使用 Class 10 或更高等级
4.  **数据格式：** RAW 格式比 VOLTS 转换更快
5.  **文件格式：** BIN 格式的开销小于 WAV 或 TDMS
6.  **客户端能力：** 流式传输客户端应用的性能

|

最高可能数据速率
============================

使用以下设置可达到最高数据速率：

1. :ref:`Command line client <stream_command_client>`
2. **RAW** data format (no conversion)
3. **Binary (BIN)** file type (minimal overhead)
4. **Web interface disabled** (no UI updates)
5. **Single streaming mode** (ADC or DAC, not both)

这是最高效的数据传输方式，因为数据通过网络发送前不会进行转换。

|

2. 计算最大采样频率
*******************************************

可以使用以下计算确定流式传输的最大**连续**采样频率：

.. math::

    f_{S, max} = \frac{v_{max}}{N \times BpS}

其中：

* :math:`f_{S, max}` - 最大连续采样频率
* :math:`v_{max}` - 所选流式传输模式的最大数据速率（本地流式传输为 10 MB/s，OS 2.07-43+ 网络流式传输为 62.5 MB/s）
* :math:`N` - 选择用于数据采集的输入通道数（1、2、3 或 4）
* :math:`BpS` - 每采样字节数，即表示每个采样所用的字节数（8-bit 分辨率为 1，16-bit 分辨率为 2）

.. note::

    这些计算适用于**连续流式传输**。对于短时突发采集，可以利用 DDR 内存缓冲区实现最高 125 MS/s 的更高采样率（见下方“短时高速采集”）。

|

计算示例
=====================

.. note::

    以下示例使用 **62.5 MB/s** 的网络流式传输限制（OS 2.07-43 或更高版本）。对于 OS 1.04-28 至 2.05-37，请改用 **20 MB/s**。

示例 1：网络流式传输、单通道、16-bit
------------------------------------------------------

* :math:`v_{max}` = 62.5 MB/s = 62,500,000 Bytes/s
* :math:`N` = 1 channel
* :math:`BpS` = 2 Bytes (16-bit)

.. math::

    f_{S, max} = \frac{62,500,000}{1 \times 2} = 31,250,000 \text{ samples/s} = 31.25 \text{ MS/s}

|

示例 2：网络流式传输、双通道、8-bit
---------------------------------------------------

* :math:`v_{max}` = 62.5 MB/s = 62,500,000 Bytes/s
* :math:`N` = 2 channels
* :math:`BpS` = 1 Byte (8-bit)

.. math::

    f_{S, max} = \frac{62,500,000}{2 \times 1} = 31,250,000 \text{ samples/s} = 31.25 \text{ MS/s}

|

示例 3：本地（SD 卡）流式传输、单通道、16-bit
--------------------------------------------------------------

* :math:`v_{max}` = 10 MB/s = 10,000,000 Bytes/s
* :math:`N` = 1 channel
* :math:`BpS` = 2 Bytes (16-bit)

.. math::

    f_{S, max} = \frac{10,000,000}{1 \times 2} = 5,000,000 \text{ samples/s} = 5 \text{ MS/s}

|

示例 4：网络流式传输（旧 OS）、单通道、16-bit
-----------------------------------------------------------------

对于网络限制为 20 MB/s 的 OS 1.04-28 至 2.05-37：

* :math:`v_{max}` = 20 MB/s = 20,000,000 Bytes/s
* :math:`N` = 1 channel
* :math:`BpS` = 2 Bytes (16-bit)

.. math::

    f_{S, max} = \frac{20,000,000}{1 \times 2} = 10,000,000 \text{ samples/s} = 10 \text{ MS/s}

|

短时高速采集（DMA 单缓冲区模式）
=============================================================

.. note::

    **单缓冲区模式（DMA）：** :ref:`深度内存采集（DMA） <deepMemoryAcq>` 支持专用的 **one buffer mode**，数据会以完整 ADC 核心时钟速度（最高 125 MS/s）直接捕获到 DDR 内存缓冲区，而不受 true streaming mode 的 62.5 MB/s 网络吞吐限制。缓冲区填满后，采集停止，数据随后传输到计算机。此模式可通过 :ref:`流式传输命令行客户端 <stream_command_client>` 触发，或直接使用 SCPI、Python API 和 C++ API 命令配置。

    全速捕获时可采集的最大数据量由预留 DDR 缓冲区大小决定。缓冲区填满后，后续采集受最大连续流式传输速率限制（网络 62.5 MB/s、SD 卡 10 MB/s）。有关配置预留内存区域的详情，请参阅 :ref:`深度内存模式 <deepMemoryMode>`。

|

3. 数据包大小限制
***************************

为提高应用效率，通过网络发送的数据包（块）存在最小大小限制。在高抽取率下影响尤其明显，因为填满一个块后才能通过网络发送，可能需要较长时间。

.. warning::

    如果在数据块填满前停止流式传输，已采集数据会被丢弃。因此，保存文件的大小可能为 **0 bits**。

|

最小数据块大小
====================

以下是按文件类型和单位列出的最小数据块限制：

+--------------------+-----------------+----------------+----------------+
| 文件类型 \\ 单位   | WAV             | TDMS           | BIN            |
+====================+=================+================+================+
| VOLTS              | 128.043 kb      | 128.133 kb     | 64.090 kb      |
+--------------------+-----------------+----------------+----------------+
| RAW                | 64.043 kb       | 64.133 kb      | 64.090 kb      |
+--------------------+-----------------+----------------+----------------+

|

4. 数据生成限制
*******************************

数据生成过程与 ADC 流式传输的限制不同，因为数据路径相反。数据必须通过网络接收并处理后才能发送到 FPGA，因此预期性能低于 ADC 流式传输。

有关 DAC 流式传输架构及这些限制成因的详情，请参阅 :ref:`技术细节 <streaming_technical_details>`。

DAC 速率限制
=====================

以下是两种模式下 **dac_rate** 变量的限制：

.. tabs::

    .. group-tab:: OS 3.00-57 或更高版本

        * **One-pack mode：** **dac_rate** 最大为 125 MHz（125 MS/s）
        * **True streaming mode：** 稳定的 **dac_rate** 最大约为 62.5 MHz（62.5 MS/s）

        .. warning::

            在 True streaming 模式下将 DAC 速率设置为高于 62.5 MHz，可能导致数据丢失和信号生成不稳定。

    .. group-tab:: OS 2.07-43 至 2.07-51

        * **One-pack mode：** **dac_rate** 最大为 125 MHz（125 MS/s）
        * **True streaming mode：** 对于 16-bit 分辨率，稳定的 **dac_rate** 最大约为 5 MHz（5 MS/s）

        .. warning::

            在 True streaming 模式下将 DAC 速率设置为高于 5 MHz，可能导致数据丢失和信号生成不稳定。

.. note::

    :ref:`深度内存生成（DMG） <deepMemoryGen>` 同样支持 **one buffer mode** 和 **true streaming mode** （见上文）。
    在 one buffer mode 下可使用完整 DAC 核心时钟速率（125 MHz），最大输出信号频率为 1.953 MHz（最小缓冲区为 64 个采样，每个缓冲区一个周期）。在 true streaming mode 下，数据速率限制为 62.5 MB/s，输出波形在连续采样之间**保持不变**（零阶保持，不进行 FPGA 插值）。DMG 的 true streaming mode 比 one buffer mode 需要显著更多的预留 DDR 内存；如果预留内存不足，应用和代码会发出警告。详情请参阅 :ref:`深度内存生成 <deepMemoryGen>`。

|

DAC 性能建议
=================================

对于基于文件的 DAC 生成，建议：

1. **尽可能使用 one-pack mode** - 使波形足够小，以便放入一个 ``block_size``。如果波形变大，请增加预留的 :ref:`DMM memory <stream_memory_config>`。
2. **将块大小设置为 2 MB 或更大** - 更大的块大小可减少传输开销，并给软件更多处理数据的时间。在 true streaming mode 下，使用实际可行的最大块大小。
3. **每通道至少使用 1024 个采样** - 波形绝对最小大小为 128 Bytes（64 或 128 个采样），但建议至少使用 1024 个采样，以避免 C++ 程序开销造成的不一致。
4. **保持波形大小对齐** - 波形大小应为 128 Bytes 的倍数（16-bit 分辨率下为 64 个采样），以确保正确对齐并避免数据损坏。
5. **使信号长度匹配块大小** - 理想情况下，信号应完全放入所选块大小中。

|

其他因素
===================

* **网络 USB 网卡：** 使用时可能限制最大数据速率
* **文件大小限制：** WAV 文件格式最大为 4 GB，因此最多约 2.68 亿个采样（16-bit 分辨率）
* **分辨率：** DAC 流式传输当前限制为 16-bit 分辨率（如果板卡输出分辨率更低，则以板卡输出分辨率为准）

.. note::

    DAC 流式传输当前限于 16-bit 分辨率以及 WAV 或 TDMS 文件格式。

|

5. 性能优化提示
*********************************

要最大化流式传输性能，请结合使用上述设置和以下提示：

ADC 流式传输优化
===========================

1. 使用 **RAW** 数据格式而不是 VOLTS
2. 使用 **BIN** 文件格式以获得最小开销
3. 流式传输期间禁用 Web 界面
4. 根据采样率使用适当的 :ref:`块大小 <stream_memory_config>`
5. 将板卡连接到路由器，以获得稳定的网络流式传输
6. 本地流式传输使用高质量 Class 10 SD 卡
7. 禁用未使用的通道
8. 不需要 16-bit 精度时使用 8-bit 分辨率

|

DAC 流式传输优化
===========================

1. 遵循上面的 DAC 性能建议，设置块大小、波形大小和 DMM 内存用量。
2. 避免以最大速率同时进行 DAC 和 ADC 流式传输。

|
