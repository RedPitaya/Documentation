.. _os_compatibility:

###########################
OS 版本兼容性
###########################

本页介绍官方 Red Pitaya OS 与不同硬件代际的兼容性，以及在较新硬件上运行旧 OS 版本的说明。

.. contents::
   :local:
   :backlinks: none

|


推荐 OS 版本
========================

**Gen 2 板卡** （STEMlab 125-14 Gen 2、PRO 变体、TI 变体）：

* **要求**：OS 版本 2.07-43 或更高
* **TI 板卡**：不兼容旧 OS 版本；尝试运行旧版本可能导致故障或损坏

**Original Generation 板卡** （STEMlab 125-14、SDRlab 122-16、SIGNALlab 250-12 等）：

* **兼容**：所有 OS 版本（0.9、1.04、2.00+）
* **推荐**：使用最新稳定 OS 版本以获得最佳性能和功能

|


在 Gen 2 板卡上运行旧 OS 版本
==========================================

.. warning::

    由于根本性的硬件变化，**TI 板卡不兼容早于 2.07-43 的 OS 版本**。尝试在 TI 板卡上运行旧 OS 版本可能导致故障或永久损坏。

名称中包含“Gen 2”标识的板卡（例如 STEMlab 125-14 Gen 2、STEMlab 125-14 PRO Gen 2、STEMlab 125-14 PRO Z7020 Gen 2）在技术上向后兼容部分旧 OS 版本。

但是，由于以下原因，强烈不建议在 Gen 2 板卡上运行旧 OS 版本：

* 不支持新的硬件功能（E3 连接器）
* 可能出现校准问题
* 官方不支持此配置

|

OS 2.00 版本（早于 2.07-43）
---------------------------------------

**问题**：这些 OS 版本包含板卡 ID 检查机制，会阻止在 Gen 2 硬件上启动。

**解决方法** （不受支持）：

要绕过板卡 ID 检查，必须修改启动脚本。这需要：

1. 修改 |u-boot.script| 启动脚本以跳过板卡 ID 验证（或添加 Gen 2 ID）
2. 重新构建启动脚本并将其刷写到 SD 卡
3. 在投入生产前进行充分测试
4. 了解当前运行的是不受支持的配置

.. warning::

    Red Pitaya 不为此配置提供官方支持。使用风险由你自行承担。

.. |u-boot.script| replace:: :rp-github:`u-boot.script <RedPitaya/blob/master/patches/u-boot/u-boot.script>`

|

OS 1.04 及更早版本
--------------------

**兼容性**：这些 OS 版本不包含板卡 ID 检查，无需修改即可在 Gen 2 硬件上启动。

**关键问题 - 校准格式**：

OS 1.04 及更早版本使用旧校准格式，与 Gen 2 的校准数据不兼容。

**降级前的必要步骤**：

1. **备份当前校准数据** （OS 2.07-43+）
2. 使用 :ref:`校准命令行工具 <calib_util>` 将 **校准格式恢复** 为与 OS 1.04 兼容的旧格式。
3. **然后** 安装旧 OS 版本
4. **充分测试** - 模拟 I/O 性能可能不同

.. danger::

    如果未先恢复校准格式就安装 OS 1.04，模拟输入和输出将无法正确测量。

|

自定义 OS 构建
-----------------

不检查板卡 ID 的**自定义 OS 构建**可能可以在 Gen 2 硬件上运行：

* 必须在目标硬件上充分测试
* 如果使用官方校准，应确保兼容 Gen 2 校准格式
* 可能不支持所有 Gen 2 专属功能（E3 连接器、外部时钟等）
* Red Pitaya 不提供官方支持

|


为什么 Gen 2 需要较新的 OS 版本
======================================

原因很简单：我们在 OS 2.00 中引入了自动板卡识别，因此旧 OS 版本无法识别较新的板卡 ID 版本，进而无法启动。
其他原因如下：

**需要 OS 支持的硬件改进：**

* E3 扩展板支持（额外 GPIO、QSPI 和 eMMC 启动选项）
* 非关键外设单元的部分引脚定义变化（S1 和 S2 连接器的引脚分配不同）
* 模拟硬件改进，与旧自动校准脚本不兼容

**需要 OS 支持的软件改进：**

* EEPROM 中不同的校准格式
* 不同的板卡 ID 版本

**TI 变体还有更根本的变化：**

* 使用特性不同的 ADC/DAC 芯片
* 修改了模拟信号链
* 需要完全不同的 FPGA 比特流和软件驱动

这就是旧 OS 版本无法正确支持 Gen 2 硬件的原因：它们没有新硬件所需的驱动、校准数据或配置。

|


获取帮助
=============

如果因旧应用兼容性需要运行旧 OS 版本：

1. **考虑更新应用**，使其改为使用最新 OS
2. **联系 Red Pitaya 支持**，通过 :ref:`讨论你的具体使用场景 <report_problem>` 获取帮助
3. 如果必须运行旧 OS 版本，**使用 Original Generation 硬件**

有关 OS 更新说明和官方 OS 下载，请参阅：

* :ref:`OS 更新指南 <os_update>`
* `Red Pitaya 下载 <https://redpitaya.com/downloads/>`_

|
