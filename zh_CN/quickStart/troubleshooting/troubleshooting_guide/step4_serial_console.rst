#######################################
步骤 4：串口控制台启动日志
#######################################

检查串口控制台启动日志是排查 Red Pitaya 网络连接问题的重要步骤。通过串口控制台连接 Red Pitaya 板卡，可以检查启动消息中是否存在阻止板卡连接网络的错误。此外，这也是判断 Red Pitaya 板卡是否正常工作的最后一项检查。如果板卡无法正确启动，可能存在需要进一步调查的硬件问题。

无论属于哪种情况，主要目标都是获取串口控制台启动日志，并检查启动过程中是否出现错误。

适用条件
================

在以下情况下需要检查串口启动日志：

* **状态 LED 工作异常**。这表示 Red Pitaya 板卡本身可能存在问题（接续 :ref:`步骤 2：检查状态 LED <troubleshooting_status_leds>` 章节）。
* **状态 LED 工作正常**，但 **连接板卡时遇到困难**。这表示 Red Pitaya 板卡可能正常，但仍无法连接 Red Pitaya Web 界面或 :ref:`SSH <ssh>`。

|

逐步排查串口问题
=====================================

此时需要通过 :ref:`串口控制台 <console>` 连接 Red Pitaya 板卡，并检查启动日志中的错误。请按照以下步骤操作：

建立串口控制台连接
--------------------------------------

1. **为板卡上电**。按正常方式为板卡上电并连接以太网线。
#. **连接串口控制台**。板卡启动后，用 :ref:`串口控制台 <console>` 线缆连接 Red Pitaya 板卡和计算机。按照 :ref:`串口控制台连接指南 <console>` 建立连接，然后返回本节继续执行后续步骤。

|

检查启动日志
---------------------

3. **存在启动日志**。Red Pitaya 应输出启动顺序信息。如果没有任何反馈，Zynq SoC 很可能已经损坏。请 :ref:`联系我们 <report_problem>`。
#. **U-Boot 正在启动**。检查 Zynq SoC（U-Boot）是否启动（消息 *Autoboot will start in 3...2...1... (Hit any key to stop)*）。
#. **Linux 内核正在启动**。对于 OS 2.07 及更旧版本，检查 Linux 内核启动过程是否出现 :ref:`循环迹象 <faq_rebooting>`。如果板卡不断重启，请检查它是否为 **外部时钟板卡、外部时钟是否已连接**，以及时钟是否符合正确的 :ref:`规格 <faq_clock_specifications>`。
#. **到达 Ubuntu 欢迎消息**。如果内核启动到 Linux Ubuntu 欢迎消息且没有重启，则 Red Pitaya 硬件正常。

|

到达 Ubuntu 欢迎消息后
---------------------------------

如果板卡到达 Ubuntu 欢迎消息且没有重启，则硬件很可能正常。如果仍然无法连接，请检查以下项目：

7. **检查主机名（rp-888888）**。如果启动日志显示板卡以 ``rp-888888`` 名称启动，说明板卡可能无法从 EEPROM 读取 MAC 地址。请安装 :ref:`最新 OS 版本 <prepareSD>` 并检查问题是否仍然存在。如果仍然存在，请 :ref:`联系我们 <report_problem>`。
#. **OpenBSD failed to start 错误**。如果启动日志显示 **OpenBSD failed to start**，请等待一两分钟，因为板卡可能会重新尝试启动 OpenBSD。
#. **重启路由器和板卡**。如果 OpenBSD 问题仍然存在，请重启路由器（或清除路由器内部缓存/ARP 表）并重新启动板卡，然后再次尝试连接。
#. **在串口控制台打开时 ping Red Pitaya**。分别对 Red Pitaya IP 地址和 ``rp-xxxxxx.local`` 使用 ``ping`` 命令。
#. **检查 IP 分配**。在串口控制台中确认以太网接口已获得 IP 地址。如果没有分配 IP，请检查路由器的 DHCP 设置。
#. **检查本地网络限制**。某些网络会阻止设备之间的流量，例如访客网络、AP/客户端隔离或受管网络。如有可能，请在其他本地网络上测试。
