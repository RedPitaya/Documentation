############################
步骤 6：Web 应用程序
############################

本节将检查 Red Pitaya 板卡 Web 应用程序最常见的问题，以确定 Web 界面或应用程序本身是否存在故障。

.. contents:: 目录
    :local:
    :depth: 2
    :backlinks: top

|

适用条件
===============

以下情况请使用本节：

* **已经检查硬件连接且工作正常**。你已检查 :ref:`硬件连接 <troubleshooting_hardware_connections>` 并确认其正常，但 Web 界面或应用程序仍有问题。
* **可以访问 Web 界面，但应用程序工作异常**。你可以访问 Web 界面，但应用程序工作不正常或发生卡死。

|

逐步排查 Web 应用程序问题
=============================================

最可能的原因是 Web 浏览器、Web 应用程序或信号设置存在问题。

检查浏览器
------------------

1. **使用最新版 Google Chrome**。确保使用最新版 Google Chrome 作为 Web 浏览器。Web 界面的某些功能在其他浏览器或较旧的 Chrome 版本中可能无法正常工作。
#. **清除浏览器缓存和 Cookie**。清除浏览器缓存和 Cookie，然后再次尝试访问 Web 界面。

|

检查 Web 应用程序
--------------------------

3. **更新 OS**。如果 Web 界面卡死或反复重新加载，请 :ref:`将 OS 更新到最新版本 <update_os>`。使用直连方式时，这是较旧 Red Pitaya 固件（OS 1.04 及更旧版本）的常见问题。
#. **删除板卡应用程序数据**。访问 :ref:`系统信息菜单 <system_info>` 并选择 **Delete application data**，清除 Red Pitaya 板卡上的应用程序数据。这会将所有应用程序设置重置为默认值，并应能解决应用程序数据损坏造成的问题。

|

检查信号设置
--------------------------

5. **Web 界面中不显示信号**。如果可以访问 Web 界面且应用程序正常工作，但 Red Pitaya 的输入或输出端没有收到任何信号，请检查以下项目：

    * **显示信号**。确认输入设置中的 **Show** 按钮已高亮，确保 Web 界面显示信号。
    * **输入跳线**。检查 :ref:`输入跳线 <jumper_pos>`。跳线有时会接触不良，需要拔下后重新插入。如果跳线松动或缺失，请予以更换。
    * **校准设置**。错误的校准会使 Red Pitaya 显示不正确的测量结果，甚至看起来完全检测不到信号。这同时适用于 Red Pitaya 的输入和输出。检查 Web 界面中的 :ref:`直流校准设置 <calibration_app>`，将其重置为 **默认值**，并在必要时重新校准板卡。这会把用户校准更新为最新格式，通常能够解决 Web 界面不显示信号的问题。

|
