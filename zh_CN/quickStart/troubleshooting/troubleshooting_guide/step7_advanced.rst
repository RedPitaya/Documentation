步骤 7：高级故障排除
###################################

这是故障排除指南的最后一节。如果已经完成前面所有章节但问题仍然存在，本节提供的一些针对特定情形的排查步骤可能有助于解决问题。

适用条件
===============

以下情况请使用本节：

* **完成前面的所有故障排除步骤后问题仍然存在**。你已检查上述所有章节，能够访问 Web 界面和应用程序，但问题仍未解决。


逐步进行高级故障排除
=====================================

最可能的原因是某个更具体的硬件或软件问题。请按顺序检查以下项目：

软件和固件检查
----------------------------

1. **从 1.04 或更旧的 OS 更新**。如果从 1.04（或更旧版本）更新到 2.00 OS 或更高版本，请查看 GitHub issue |#250| 和 |#254|。
#. **每夜构建版**。查看 :ref:`每夜构建版变更日志 <nightly_builds>` 中是否有相关更新。
#. **已知软件问题**。查看 :ref:`软件章节 <known_sw_issues>` 中的已知软件问题。

|

硬件专项检查
------------------------

4. **E2 连接器上的 UART TX 引脚**。对于 **初代** 板卡型号，请检查 :ref:`E2 <E2_orig_gen>` 连接器上的 UART TX 引脚在启动前或启动期间是否被驱动为高电平（3V3）。此时板卡会正常启动，但无法访问 Web 界面，也无法通过 :ref:`SSH <ssh>` 连接。
#. **已知硬件问题**。查看 :ref:`初代 <known_hw_issues_orig_gen>` 和 :ref:`第二代 <known_hw_issues_gen2>` 板卡的已知硬件问题。

|

系统恢复检查
----------------------

5. **内核崩溃**。当操作系统检测到无法恢复的错误时会发生内核崩溃，常见原因包括程序破坏或访问无效内存、硬件问题，或软件组件之间发生冲突。请重新安装 :ref:`最新版官方 Red Pitaya OS <prepareSD>`，并检查问题是否仍然存在。如果仍然存在，请 :ref:`联系我们 <report_problem>`。

|

后续步骤
=============

希望本故障排除指南对你有所帮助，并已成功解决问题。如果问题仍然存在，请 :ref:`联系我们 <report_problem>` 并提供与问题有关的全部信息；如有可能，请一并提供 :ref:`下载的系统报告 <system_info>`。
